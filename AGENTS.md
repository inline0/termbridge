# Termbridge

Keep repository-specific agent guidance in `AGENTS.md` only. Do not add
duplicate instruction files or forwarding stubs.

Local terminal beaming CLI. Exposes your terminal via a public HTTPS URL for mobile access.

## Project Overview

Termbridge is an open-source CLI that runs entirely on the user's machine. It starts a local web server with a browser UI and WebSocket endpoint, backed by tmux PTY streaming or a Daytona sandbox. A Cloudflare tunnel exposes the local server on a public HTTPS URL with QR code for easy mobile access.

**Package name:** `termbridge`
**License:** MIT

The Daytona E2E tests use a sibling repository:


The test app's `.env` file contains:


The `TERMBRIDGE_E2E_DAYTONA=1` flag enables the Daytona tests. Without it, they're skipped.

## HTTP Endpoints

All termbridge routes use `/__tb/` prefix to avoid conflicts with proxied apps.

| Endpoint                                | Description                          |
| --------------------------------------- | ------------------------------------ |
| `GET /__tb/s/:token`                    | Token redemption → cookie → redirect |
| `GET /__tb/api/terminals`               | List terminals                       |
| `POST /__tb/api/terminals`              | Create terminal                      |
| `GET /__tb/api/csrf`                    | Get CSRF token                       |
| `GET /__tb/api/config`                  | Get config                           |
| `GET /__tb/healthz`                     | Health check                         |
| `WS /__tb/ws/terminal/:id?csrf=<token>` | Terminal WebSocket                   |
| `GET /`                                 | Redirect to app (or proxy)           |

## Security

### One-time Token

- 128-bit random, base64url encoded
- SHA-256 hashed server-side
- 90-second TTL, single use

### Session

- 144-bit session ID in HttpOnly cookie
- 30-minute idle timeout, 8-hour max
- CSRF token for WebSocket protection

### Input Limits

- HTTP request body: 64KB max
- WebSocket message: 1MB max
- Terminal input per message: 64KB max

## Data Flow

```
Browser → Public URL (tunnel) → Local HTTP/WS → tmux/sandbox
```

1. Browser connects to Cloudflare tunnel URL
2. `GET /__tb/s/:token` redeems token, sets session cookie
3. Redirect to `/__tb/app`, load React SPA
4. Fetch CSRF token via `GET /__tb/api/csrf`
5. WebSocket to `/__tb/ws/terminal/:id?csrf=<token>`
6. Server streams PTY output to client
7. Client sends input/resize/control back

### Proxy Mode

- UI shows Terminal/Preview tabs
- Non-`/__tb/` requests proxied to target app
- Preview tab shows iframe pointing to `/`

### Direct Mode (Daytona)

- Server runs inside sandbox
- No Cloudflare tunnel needed
- Uses Daytona's preview URLs

## Workspace Rules

Use `pnpm run setup` to install the frozen lockfile and Chromium. All packages are
ES modules under `packages/*`. The root is private; only `packages/cli`
(`termbridge`) is published. Internal packages remain bundled implementation
boundaries, not separately published APIs.

Keep external versions in the root `pnpm-workspace.yaml` catalog and consume
those entries with `catalog:`. Internal dependencies must use `workspace:*`.
`pnpm lint` checks manifest consistency and dependency cycles. Native build
scripts require an explicit entry in `allowBuilds`; do not disable this check.

Use Oxfmt at 80 columns, double quotes, no semicolons, ES5 trailing commas, and
sorted imports without blank groups. Use Oxlint's correctness and type-aware
rules without suppressing failures. Relative TypeScript imports include their
`.ts` or `.tsx` extension. Document exported source functions, classes, interfaces,
and type aliases with JSDoc, including parameter and return descriptions. Tests,
integration helpers, and declarations are exempt from export documentation.
The documentation lint plugin is adapted from inline0/sleekos; retain its NOTICE.

`pnpm check` runs formatting, lint, type checks, tooling tests, unit tests with
100% coverage, and all package builds. `pnpm verify` additionally runs real CLI
and browser integration tests and the packed consumer smoke test. The CLI still
supports Node.js 20+; CI installs and exercises its tarball on Node 20, 22, 24,
and 26. CI runs local browser regressions using tmux and Chromium without
Cloudflare or sandbox credentials, plus `pnpm audit --prod` and
`pnpm test:local-package` to check direct sandbox archives. Installed CLI
archives use npm with lifecycle scripts disabled; only source workspace
archives require pnpm to resolve catalogs. Temporary archives are removed after
sandbox startup succeeds or rejects. Do not leave dev servers, browser processes, tmux sessions, or temporary
consumer installs running after verification. Never read or log test credentials.
